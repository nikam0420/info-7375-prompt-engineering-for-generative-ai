# Tool server evaluations

## JS3 score tool

**Declared.** Stdio JSON-RPC handshake, one tools capability, and one callable scorer. It accepts two strings, returns a score and matching literal mentions, and identifies itself as read-only and closed-world.

**Observed.** On 2026-11-25, `python3 demo.py` exchanged 13 actual wire messages with the Python server. The posting text was seeded and fictional. The client initialized, sent the initialized notification, listed the schema and called the tool. A two-signal analyst example returned 5 and keep. Empty text yielded unknown. A URL field produced a tool error. An attempted call to an unregistered action yielded a JSON-RPC error. The client verified all six replies. Both directions are preserved in `evidence/demo-wire.jsonl`.

**Implementation and trust.** The server scores supplied strings and does not open URLs or mutate external data. Optional recording appends only inside the project’s ignored `local/` folder. There is no network, subprocess execution, or outbound action in the scoring path. A compatible client can expect the supported handshake and named call. Prompts, resources, streaming, remote authentication, independent verification, and guarantees of eligibility are outside its declared API. Trust it for bounded, deterministic review prioritization with public or fictional input. Human review is required for eligibility or stronger source claims. Broader conformance and Claude interoperability remain unverified.

## MCP reference Fetch server

**Declared.** The [Fetch MCP server documentation](https://github.com/modelcontextprotocol/servers/tree/main/src/fetch) describes an Internet fetch tool accepting a URL with pagination, raw rendering and timeout options. It declares read-only and open-world behavior.

**Implementation reviewed.** In [server.py](https://github.com/modelcontextprotocol/servers/blob/main/src/fetch/src/mcp_server_fetch/server.py), the tool validates the URL, checks robots policy under default configuration, passes the address to a network fetcher, processes redirects with checks, and formats the result. The implementation distinguishes a user-invoked prompt from an autonomous tool fetch for robots handling. The fetcher can transform HTML and return a bounded slice, so the caller may receive transformed or incomplete source material. The source was inspected without executing the server.

**Client expectations and trust.** A client gets a fetch interface and should handle refusal or truncation. Open-world read-only access still sends observable requests outside the process. The behavior of optional proxy and private-address settings depends on deployment. Web content can include untrusted instructions. For this project’s three fixed boards, use the explicit allow-list collector. Consider Fetch only for reviewed public URLs with outbound policy enforced and fetched text treated as data.
